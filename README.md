# Offline RL for Flexible Job Shop Scheduling

Research-oriented Industrial Engineering / Operations Research project studying whether policies learned **offline from OR-generated scheduling decisions** can approach strong optimization and dispatching baselines without online exploration.

## Research question

Can offline reinforcement learning exploit trajectories generated by strong schedulers and remain competitive on unseen Flexible Job Shop Scheduling Problem (FJSP) instances, especially when the dataset contains mixed-quality decisions?

## Experimental design

The repository is organized around four controller families:

1. **Dispatching rules** — SPT, EDD, minimum slack and minimum processing-time assignment.
2. **OR expert** — rolling-horizon CP-SAT is the intended expert generator for larger experiments.
3. **Offline learning** — behavioral cloning and conservative Q-learning-style value learning over logged transitions.
4. **Online RL benchmark** — PPO is reserved as a comparison, not assumed to be superior.

The first implementation milestone deliberately keeps the environment compact and auditable: multi-operation jobs, alternative eligible machines, precedence constraints, machine-dependent processing times and due dates. The code includes a deterministic simulator, dataset logger and a conservative tabular offline-Q baseline suitable for unit tests and small experiments.

## Why this project is different

The purpose is not to produce another RL demo. The evaluation contract is:

- strong non-learning baselines first;
- logged datasets with explicit provenance and policy quality;
- train/validation/final-test separation;
- feasibility checked independently of reward;
- reporting of makespan, tardiness, policy latency and solver latency;
- negative results retained rather than tuned away.

## Planned research stages

### Stage 1 — auditable environment and baselines
Validate precedence, eligibility, machine availability and KPI calculations. Freeze deterministic heuristic baselines.

### Stage 2 — OR expert dataset
Add rolling-horizon OR-Tools CP-SAT and log `(state, action, reward, next_state, done, behavior_policy)` transitions. Produce expert-only, heuristic-only and mixed-quality datasets.

### Stage 3 — offline learning
Benchmark behavioral cloning, CQL and IQL. Track extrapolation error and action support, not reward alone.

### Stage 4 — independent validation
Tune only on validation instances. Freeze all hyperparameters before final testing.

### Stage 5 — OOD campaign
Stress larger job counts, tighter due dates, changed machine eligibility and processing-time shifts.

## Success criteria

A learned policy only earns promotion if it is feasible on all final instances and its decision-quality/latency trade-off is competitive with strong heuristic and optimization baselines. CP-SAT remains the reference when online solve latency is acceptable.
